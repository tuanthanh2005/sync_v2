# SyncViet Backup & Restore Verification Test Report (PHẦN 37)

**Test Date**: 2026-11-26  
**Test Environment**: Isolated Local MySQL `8.4.3` (`127.0.0.1:3306`) — Source DB: `connecthub` -> Restored into isolated test DB: `syncviet_restore_test` (dropped cleanly after verification; production untouched).

## 1. Test Procedure Executed

1. Generated a full logical gzip-compressed SQL backup using production `App\Services\Admin\DatabaseBackupService::createDatabaseBackup()` (same engine executed daily by `php artisan app:backup:database`).
2. Verified private storage placement (`storage/app/private/backups/`, completely outside `public/`) and verified **SHA-256 checksum** integrity against `backup_records.checksum`.
3. Created a brand-new empty MySQL database `syncviet_restore_test` (`utf8mb4_unicode_ci`).
4. Decompressed and imported the entire `.sql.gz` archive into `syncviet_restore_test` via `mysql.exe`.
5. Audited table counts, row parity across 15 core domain tables, password hash algorithm integrity, and Laravel `APP_KEY` encryption/decryption compatibility.
6. Dropped `syncviet_restore_test` and cleaned up the temporary test archive.

## 3. Honest Scope Limitations

- This test verified the **local baseline dataset (`6.53 MB`)**. As production database size grows (e.g., to `500 MB`–`2 GB`), backup and restore durations will increase proportionally and should be re-tested quarterly in a staging database.
- **Media Files Restore Test**: Local media storage backup/restore was verified via `Storage::fake` in automated tests; off-host media sync (e.g., R2 or external S3 backup) requires Owner configuration on production.
